# 05. 로드맵 (Roadmap)

## 1. 일정 수립 원칙

**가장 불확실한 항목을 가장 먼저 검증합니다.**

Spring Boot, JPA, MySQL, React는 구현 방법이 알려져 있어 일정 예측이 가능합니다. 반면 MCP 연동과 에이전트 루프는 "의도대로 동작하는지" 자체가 불확실합니다. 이 리스크를 후반에 두면 문제가 발견되었을 때 되돌릴 시간이 없습니다. 따라서 1~2주차에 합성 데이터, 툴 하나, 조사 루프로 이루어진 최소 구성을 먼저 끝까지 연결해 봅니다.

## 3. 중간 판단 지점 (Go/No-go)

- **2주차 종료**: 조사 루프가 안정적으로 동작하지 않으면 3주차를 루프 안정화에 다시 배정하고 검토 화면 범위를 줄입니다. MCP 연동이 비용 대비 이점이 없다고 판단되면 툴을 함수로 직접 등록하는 방식으로 전환합니다(`08_tech_stack_review.md` 2.5절).
- **5주차 종료**: 통합이 지연되면 검토 화면을 툴 호출 기록 조회와 종결 처리 중심의 최소 화면으로 줄입니다.

## 4. 병행 원칙

- 매주 `docs/progress/week-NN.md`에 완료 항목을 기록합니다. 구현 완료와 검증 완료를 구분합니다.
- 설계가 바뀌면 해당 문서(00~09)를 함께 수정합니다.
- 개발 과정에서 Claude Code와 Codex를 활용한 방식(툴 서버 테스트, 테스트 작성, 교차 리뷰 등)과 효과를 진척 기록에 남깁니다.
