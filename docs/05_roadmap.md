# 05. 로드맵 (Roadmap)

## 1. 일정 수립 원칙
**가장 불확실한 항목을 가장 먼저 검증합니다.**
Spring Boot, JPA, MySQL, React는 이미 다뤄 본 영역이므로 일정 예측이 가능합니다. 반면 MCP 연동과 에이전트 루프는 처음 다루는 영역이라 "동작하는지 자체"가 불확실합니다. 이 리스크를 후반에 두면, 막혔을 때 이미 완성된 CRUD만 남는 포트폴리오가 됩니다. 따라서 1~2주차에 최소 구성의 수직 관통(spike)을 먼저 완성합니다.

## 2. 주차별 계획 (8주 기준)

| 주차 | 목표 | 주요 작업 | 완료 기준 (검증 방법) | 리스크 수준 |
|---|---|---|---|---|
| 1 | MCP 스파이크 | CSV 일부를 SQLite/MySQL에 적재, 거래 이력 조회 MCP 툴 1개 구현, Claude Code 또는 데스크톱 앱에 연결 | Claude가 자연어 질문에 해당 툴을 호출해 실제 데이터를 답함 | 최상 |
| 2 | 에이전트 루프 스파이크 | FastAPI에서 Claude API tool use 루프 직접 구현, MCP 클라이언트 연결, 반복 상한·타임아웃 적용 | 케이스 1건에 대해 툴 호출 → 결과 반영 → 최종 텍스트까지 자동 진행, 로그 출력 | 최상 |
| 3 | MCP 툴 3종 완성 | 가맹점 리스크, 지리 이상치 툴 추가, 03_mcp_tool_spec.md 확정 | 케이스 성격에 따라 에이전트가 서로 다른 툴 순서를 선택하는 사례 2개 이상 확인 | 상 |
| 4 | 데이터·백엔드 기반 | 전처리 및 정식 적재, 엔티티 설계, 룰 엔진 구현 | 룰별 탐지 건수와 라벨 대비 정밀도 산출 | 중 |
| 5 | 백엔드-에이전트 통합 | 케이스 상태 머신, AFTER_COMMIT 이벤트로 조사 요청, 로그·보고서 영속화 | 룰 탐지부터 `REPORTED`까지 자동 진행 | 상 |
| 6 | 프롬프트·보고서 품질 | 04_agent_workflow.md 확정, 근거 인용 형식 강제, 실패 케이스 분석 | 보고서의 모든 주장이 로그 단계에 연결됨 | 중 |
| 7 | 프론트엔드 | 케이스 대시보드, 추론 로그 타임라인, 승인/반려 | 조사역 관점 전체 시연 가능 | 하 |
| 8 | 평가·문서화 | 에이전트 판단과 라벨 비교 평가, README, 아키텍처 다이어그램, 시연 영상 | 면접용 5분 시연 시나리오 완성 | 하 |

## 3. 중간 판단 지점 (Go/No-go)
- **2주차 종료 시점**: 에이전트 루프가 안정적으로 동작하지 않으면 3주차를 루프 안정화에 재배정하고, 프론트엔드 범위를 축소합니다.
- **5주차 종료 시점**: 통합이 지연되면 대시보드를 추론 로그 조회 중심의 최소 화면으로 축소합니다.

## 4. 병행 원칙
- 개발 전 과정에서 Claude Code를 사용하고, 효과가 있었던 사용 방식(예: MCP 서버 테스트, 엔티티 초안 생성, 리뷰)을 별도 노트로 기록합니다. 이는 "AI를 개발 워크플로에 통합했다"는 주장의 증거 자료가 됩니다.
- 각 주차 종료 시 해당 설계 문서(00~05)를 갱신합니다.

## 5. 이력서 어필 포인트
- "리스크가 큰 에이전트·MCP 연동을 먼저 스파이크로 검증한 뒤 익숙한 백엔드를 구축했다"는 일정 운영 방식 자체가 설계 판단력의 근거가 됩니다.
