# 07. 작업 인수인계 (Handoff)

기준일: 2026-11-12. 새 작업자(사람, Claude, Codex)가 이 문서 하나로 현재 상태와 다음 작업을 파악할 수 있도록 유지합니다. 작업 규칙은 저장소 루트의 `AGENTS.md`, 주차별 기록은 `docs/progress/`를 따릅니다.

## 1. 목표와 범위

규칙으로 의심 거래를 선별한 뒤, 조사역이 수행하는 증거 조회, 비교, 기록을 AI 에이전트가 보조합니다. 최종 판단은 사람이 내립니다. 사기 탐지 모델의 정확도 향상, 실시간 승인·차단, AI의 사기 확정은 범위 밖입니다(`00_project_charter.md`).

```
규칙 탐지 → 조사 케이스 → 기본 증거 자동 수집 → 필요한 추가 조회
        → 근거가 연결된 보고서 → 조사역 검토 → 종결 또는 추가 조사 요청
```

생성형 AI가 고정 자동화보다 나은지는 비교 실험으로 확인할 가설입니다.

**미구현·미검증**: 거래 이력 MCP 툴, 합성 데이터, Claude API 실호출, 조사 루프, Kaggle 데이터 적재, 도메인 백엔드, 검토 화면, 비교 실험.

### 환경 복원

```sh
cd investigator
uv python install 3.12
uv sync --locked
uv run --locked python --version
git config core.hooksPath .githooks   # 저장소 루트에서 한 번 실행
```

macOS에 uv가 없으면 `brew install uv`로 설치합니다. 실제 Claude 호출에만 `ANTHROPIC_API_KEY`, `CLAUDE_MODEL`을 환경 변수로 전달합니다. `.env.example`은 자동으로 로드되지 않습니다. 키, `.env`, `.venv`는 커밋하거나 공유하지 않습니다.

## 3. 설계 기준 요약

- **도메인 백엔드 (Spring Boot + JPA + MySQL)**: 규칙 탐지, 케이스 상태, 보고서, 조사역 검토 이력을 담당하며 업무 상태를 바꾸는 유일한 구성 요소입니다. 외부 호출은 트랜잭션 밖에서 수행합니다.
- **AI 조사 서비스 (Python)**: 처음에는 CLI로 실행하며 MCP 툴 서버를 stdio로 띄웁니다. 모델의 `tool_use` 요청을 검증해 MCP로 실행하고 `tool_result`로 돌려줍니다. 결과는 도메인 백엔드 API로 전달하며 DB에 쓰지 않습니다. FastAPI는 백엔드와 통합할 때 추가합니다.
- **툴 서버 (MCP)**: 읽기 전용이며 케이스에 허용된 데이터만 반환합니다. 결과에 기준 시점, 조회 기간, 표본 수, 근거 ID를 담고, 빈 결과와 오류를 구분합니다. 가맹점 지표를 실제 사기율로 부르거나 가맹점 좌표를 고객의 실측 위치로 해석하지 않습니다.
- **데이터**: 최종 데이터는 Kaggle `kartik2112/fraud-detection`(Sparkov)입니다. 초기 실험은 직접 만든 합성 데이터로 합니다. 카드 원번호는 모델에 보내지 않고, `is_fraud`는 평가 전용입니다. 대상 거래 시점 이후의 이력과 대상 거래 자체는 비교 집계에서 제외합니다.
- **보고서와 통제**: 의심 근거, 반대 근거, 정보 부족을 구분하고 주장을 근거 ID에 연결합니다. 근거 ID 존재 여부와 수치 일치를 검증합니다. 조회 실패나 호출 상한 도달로 근거가 불충분하면 조사 미완료로 남깁니다. 화면에는 모델의 내부 추론 대신 툴 호출, 결과, 검토 이력을 표시합니다.

## 4. 다음 작업: 거래 한 건을 조사하는 최소 실험

1. `docs/03_mcp_tool_spec.md`에 `get_transaction_history` 명세를 작성합니다. 입력(케이스 또는 대상 거래 식별자)과 서버가 강제할 조회 범위·기준 시점을 정합니다. 출력에는 비교 기간, 거래 수, 평균 금액, 근거 거래 ID를 넣고, 표본 부족과 오류의 표현을 정합니다.
2. `data/fixtures/`에 합성 데이터(고액, 평소와 유사, 이력 부족, 원거리 이동, 다른 카드·이후 거래 혼입)를 만들고 `investigator/`에 툴을 구현합니다.
3. API 키 없이 직접 만든 MCP 클라이언트로 툴을 호출해 검증합니다. 같은 서버를 Claude Code에도 연결해 호출합니다.
4. Claude API를 연결해 호출 상한이 있는 조사 루프와 근거 ID가 포함된 보고서를 구현합니다. 루프 로직은 가짜 클라이언트로 테스트합니다.
5. 이후 가맹점·지리 툴, 도메인 백엔드 케이스 흐름, 검토 화면 순서로 연결합니다.

**첫 단계 완료 기준**: 합성 거래 한 건에서 실제 MCP 호출로 시점에 맞는 이력을 받고, 보고서의 수치와 근거 ID를 툴 결과와 대조할 수 있으며, 조회 실패 시 조사 미완료로 남습니다.

## 5. 평가 계획

같은 데이터와 권한에서 A) 수동 조사, B) 고정 조회와 템플릿 보고서, C) 코파일럿을 비교합니다. 조사역의 검토·기록 시간과 시스템 처리 시간은 따로 측정합니다. 필수 근거 누락률, 사실·수치 오류, 수정량, 호출 수, 비용, 지연을 기록합니다. 1차 탐지의 정밀도·재현율은 조사 품질과 별개로 평가합니다. 합성 데이터에서 나온 결과를 실제 운영 효과로 일반화하지 않습니다.
