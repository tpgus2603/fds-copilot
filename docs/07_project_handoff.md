## 설계 기준

- **Spring Boot + JPA + MySQL**: 탐지 룰, 케이스 상태, 보고서 및 조사역 검토 이력을 담당합니다. 외부 모델 호출을 DB 트랜잭션 밖에서 수행합니다. Spring AI 의존성이 있지만, 첫 실험의 모델 호출은 Python이 담당합니다.
- **Python MCP + Claude Messages API**: 처음에는 Python 클라이언트가 로컬 MCP 서버를 stdio로 실행합니다. 모델의 `tool_use` 요청을 애플리케이션이 검증하고 MCP로 실행한 뒤 `tool_result`로 반환합니다. FastAPI는 Spring과 HTTP 통합할 때 추가합니다. MCP 도구는 읽기 전용이며 케이스에 허용된 데이터만 반환합니다.
- **데이터**: 최종 후보는 Kaggle `kartik2112/fraud-detection`의 Sparkov 합성 카드 데이터입니다. 첫 실험은 소량의 직접 작성한 합성 데이터로 시작합니다. 카드 원번호는 모델에 보내지 않고, `is_fraud`는 조사 경로에서 분리해 평가 전용으로 사용합니다. 대상 거래 시점 이후의 이력과 대상 거래 자체를 비교 집계에서 제외합니다.
- **증거**: 거래 이력, 가맹점·업종 지표, 지리적 이상치 도구를 단계적으로 구현합니다. 수치는 코드가 계산하고 도구 결과에 기준 시점·조회 기간·표본 수·근거 ID를 담습니다. 가맹점 지표를 실제 사기율로 부르거나 가맹점 좌표를 고객의 실측 위치로 해석하지 않습니다.
- **보고서와 통제**: 의심 근거, 반대 근거, 정보 부족을 분리하고 주장을 근거 ID에 연결합니다. 링크 존재 여부와 수치 일치를 검증합니다. 빈 이력과 조회 실패를 구분하고, 실패나 호출 상한 도달로 근거가 불충분하면 조사 미완료로 남깁니다. 화면에는 모델의 내부 추론 대신 도구 호출·관찰 결과·검토 이력을 표시합니다.

## 다음 작업: 거래 한 건을 조사하는 최소 실험

1. `docs/03_mcp_tool_spec.md`에 `get_transaction_history` 명세를 작성합니다. 케이스 또는 대상 거래 식별자와 서버가 적용할 조회 범위·기준 시점을 정합니다. 출력에는 비교 기간, 거래 수, 평균 금액, 근거 거래 ID를 넣고, 표본 부족 및 오류의 표현을 명시합니다.
2. `investigator/`에 고액 거래, 과거 패턴과 유사한 거래, 이력 부족 사례를 재현할 합성 데이터를 만들고 도구를 구현합니다.
3. Claude 키 없이 MCP 클라이언트로 실제 도구를 호출합니다. 다른 카드와 조사 시점 이후 거래가 포함되지 않는지, 빈 이력과 오류가 구분되는지 검증합니다.
4. Claude API를 연결하고, 제한된 도구 호출 루프와 근거 ID가 포함된 보고서를 구현합니다. 키가 없으면 실제 호출 여부를 미검증으로 기록하고 로컬 검증을 완료합니다.
5. 최소 실험을 통과하면 가맹점·지리 도구, Spring 케이스 흐름, React 검토 화면 순서로 연결합니다.

첫 단계 완료 기준: 합성 거래 한 건에서 **실제 MCP 호출로 시점에 맞는 이력을 받고**, 보고서 수치·근거 ID를 응답과 대조할 수 있으며, 조회 실패 시 조사 미완료로 남습니다.

## 이후 평가와 협업 방식

동일한 데이터와 권한에서 A) 사람이 조회·기록하는 기본 화면, B) 고정 조회와 템플릿 보고서, C) 기본 증거에 선택적 추가 조회와 AI 보고서를 더한 코파일럿을 비교합니다. 사람의 직접 검토·기록 시간과 시스템 준비 시간은 따로 측정합니다. 필수 근거 누락률, 사실·수치 오류, 수정량, 호출 수·비용·지연을 기록합니다. 1차 탐지 정밀도·재현율은 조사 품질과 별개로 평가합니다. 합성 데이터에서 나온 결과를 실제 운영 절감 효과로 일반화하지 않습니다. 중복 알림 묶기와 조사 결과를 활용한 룰 개선은 후속 범위입니다.
