# 00. 프로젝트 헌장 (Project Charter)

## 1. 프로젝트 목적

| 증명 목표 | 구체적 증거 |
|---|---|
| 카드 도메인 실무 이해 기반의 시스템 설계 능력 | 룰 기반 1차 탐지 → 조사 → 사람의 최종 판단으로 이어지는 FDS 업무 흐름을 시스템으로 모델링 |
| Claude Code, MCP, AI 에이전트의 개발 워크플로 통합 능력 | MCP 서버 3종 직접 구현, Claude tool use 기반 ReAct 루프 구현, 개발 과정 자체에 Claude Code 활용 |

## 2. 프로젝트 정의

**이상거래(FDS) 조사 코파일럿**

1. 규칙 기반 엔진이 거래를 1차 탐지하여 조사 케이스를 생성합니다.
2. AI 에이전트가 MCP 툴(거래 이력 조회, 가맹점 리스크 조회, 지리적 이상치 계산)을 **순차적으로, 스스로 판단하여** 호출하며 케이스를 조사합니다.
3. 에이전트는 수집한 근거를 인용한 조사 보고서를 생성합니다.
4. 사람(조사역)이 보고서를 검토하여 최종 승인 또는 반려합니다.

### 범위 밖 (Non-goals)
- ML 기반 사기 탐지 모델의 정확도 경쟁 (Kaggle 스코어 경쟁이 목적이 아님)
- 실시간 승인 경로(authorization path)에 대한 인라인 차단
- 에이전트의 자동 확정 판정 (최종 판단은 항상 사람)

## 3. 초안 비교 및 재평가 결과

> 주의: 이전 대화에서 비교했던 개별 초안의 목록과 점수는 현재 문서 작성 시점의 자료에 포함되어 있지 않습니다. 아래는 선택 근거를 평가 기준 중심으로 정리한 것이며, 비교했던 초안 명칭과 점수는 추후 보완이 필요합니다.

### 3.1 평가 기준
| 기준 | 설명 |
|---|---|
| 도메인 적합성 | 현재 직무(카드)와 목표 직무(금융 IT)의 연결 고리가 명확한가 |
| AI 에이전트 필연성 | 에이전트가 "있으면 좋은 것"이 아니라 구조적으로 필요한가 |
| 기술 스택 재사용 | Spring Boot/JPA/MySQL 등 보유 역량을 증거로 활용할 수 있는가 |
| 데이터 확보 가능성 | 공개 데이터로 현실적인 시나리오를 재현할 수 있는가 |
| 면접 서사 | 30초 안에 문제-해결-결과를 설명할 수 있는가 |
| 구현 리스크 | 정해진 기간 안에 완주 가능한가 |

### 3.2 FDS 조사 코파일럿을 선택한 근거

1. **에이전트가 구조적으로 필요합니다.**
   조사 업무는 "다음에 무엇을 확인할지가 이전 확인 결과에 따라 달라지는" 탐색 과정입니다. 예를 들어 고액 거래라면 이력을 먼저 보고, 이력상 평소와 다른 지역이라면 지리 이상치를 계산하는 식입니다. 이 분기 구조는 고정된 파이프라인보다 ReAct(추론-행동-관찰 반복) 루프에 자연스럽게 대응되므로, 에이전트 도입의 정당성이 설계 단계에서 설명됩니다.

2. **Human-in-the-loop가 금융 규제 환경과 부합합니다.**
   금융권은 AI의 판단 책임 소재와 설명 가능성을 요구합니다. "AI가 조사하고 사람이 결정한다"는 구조는 이 요구를 정면으로 반영하며, 면접에서 규제 이해도를 보여줄 수 있는 지점입니다.

3. **보유 스택을 그대로 활용합니다.**
   룰 엔진과 케이스 관리는 Spring Boot + JPA의 트랜잭션·상태 관리 역량을, 에이전트 계층은 새로 학습하는 역량을 보여줍니다. 익숙한 영역과 새로운 영역의 경계가 명확하여 학습 리스크가 한 곳(에이전트/MCP)에 집중됩니다.

4. **해석 가능한 데이터가 존재합니다.**
   Sparkov 시뮬레이션 데이터는 가맹점, 카테고리, 고객 및 가맹점 좌표 등 사람이 읽을 수 있는 필드를 제공하므로, 에이전트의 근거 문장("고객 거주지에서 1,200km 떨어진 가맹점")이 실제 값에 기반할 수 있습니다.

### 3.3 인정하는 트레이드오프
| 트레이드오프 | 대응 |
|---|---|
| 시뮬레이션 데이터이므로 실제 사기 패턴과 다를 수 있음 | 문서와 README에 한계를 명시하고, 목적이 "조사 워크플로 설계"임을 강조 |
| LLM 호출 비용과 지연 | 1차 룰 탐지로 에이전트 호출 대상을 소수 케이스로 제한 |
| 에이전트 비결정성 | 추론 로그 전량 저장 및 시각화, 최종 판단은 사람 |

## 4. 성공 기준
- 룰 탐지부터 조사역 승인/반려까지 전체 흐름이 로컬 환경에서 한 번에 시연됩니다.
- 에이전트가 최소 2개 이상의 MCP 툴을 상황에 따라 다른 순서로 호출하는 사례를 재현할 수 있습니다.
- 보고서의 모든 주장이 툴 호출 결과로 추적 가능합니다.
- 추론 로그가 프론트엔드에서 단계별로 시각화됩니다.

## 5. 이력서 어필 포인트
- "카드 FDS 조사 업무를 MCP 기반 AI 에이전트로 자동화하고, 최종 판단은 조사역에게 두는 Human-in-the-loop 구조를 설계"
- 에이전트 도입 이유를 기술 유행이 아니라 업무 구조(조건부 탐색)로 설명할 수 있다는 점이 핵심 차별점입니다.
